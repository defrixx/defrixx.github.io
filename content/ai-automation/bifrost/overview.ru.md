# Интеграция с Bifrost

Интеграция с Bifrost объединяет проверки Prompt Guard и Prompt Integrity при приеме запросов приложением и перед окончательной отправкой провайдеру. Она также позволяет подготовить пять самостоятельных скиллов для Skills Repository в Bifrost и проверить поведение модели через настроенный маршрут шлюза в пределах заданных сценариев. Для работы используется HTTP-интерфейс Chat Completions в Bifrost OSS; отдельный форк шлюза и подписка Enterprise Guardrails не требуются.

[Исходники и настройка](https://github.com/defrixx/Product-security-skills/tree/main/integrations/bifrost) | [Скиллы и инструменты](../security-skills/overview.ru.md)

## Возможности и результаты

| Задача | Входные данные | Результат |
| --- | --- | --- |
| Проверить текстовый чат | Сообщения JSON в UTF-8 с метками источников и политика приложения с закрепленным хешем | Проверенный текст ответа ассистента; при отклонении операция прекращается |
| Защитить целостность запроса | Согласованный эталон с моделью, системной инструкцией, параметрами и определениями инструментов | Проверка и отправка одного и того же сериализованного снимка запроса на выбранной границе |
| Подключить клиентов с поддержкой агентов | Согласованные контракты обмена с агентом, фиксированные схемы инструментов и ответы JSON или SSE в пределах заданных ограничений | Проверенное содержимое и предложения вызовов инструментов после проверки всего ответа |
| Выполнить разрешенные вызовы | Проверенные предложения вызовов, контекст рабочего процесса с данными аутентифицированного пользователя, функция авторизации и обработчики приложения | Однократное выполнение группы вызовов и проверенные результаты для следующего обращения к модели, которое приложение запускает явно |
| Импортировать скиллы | Доверенная локальная копия репозитория и новый каталог подготовки | Пять самостоятельных каталогов скиллов и манифест SHA-256 |
| Исследовать поведение маршрута | Адрес шлюза, запрошенный маршрут и ожидаемая модель в ответе | Результаты отдельных сценариев Model Security Eval, привязанные к маршруту |

В явно выбранном режиме `inspect-and-drop` текст рассуждений в поддерживаемых структурированных полях проверяется вместе с видимым содержимым, затем удаляется перед выдачей. Поток SSE полностью принимается и проверяется до начала выдачи клиенту. После проверки формируется новый ответ SSE, поэтому клиент получает его только после завершения исходного ответа. Для выполнения каждого вызова нужны явное разрешение приложения и предоставленный им обработчик. Приложение отвечает за привязку истории к пользователю и его рабочему процессу, проверку разрешений непосредственно при выполнении действия, ограничения ввода-вывода и сохранение идемпотентности при перезапусках.

## Выбор границы

`GuardedClient` проверяет текстовые обращения, явно направленные через этот клиент. Входной HTTP-фасад с аутентификацией по токену принимает только `POST /v1/chat/completions` со строго заданной структурой запроса. `ProviderBoundary` проверяет окончательный снимок запроса провайдеру и управляет сериализацией и единственной отправкой для выбранного контракта провайдера.

Чтобы все клиентские запросы проходили эти проверки, предоставьте клиентам доступ к фасаду, оставьте Bifrost в частной сети шлюза и разместите службу окончательной отправки между этой сетью и отдельной сетью модели. Ограничьте прямой доступ и разделите учетные данные шлюза и модели. Настройте маршрутизацию, кеширование и повторные попытки в соответствии с выбранным контрактом. При удаленном доступе обеспечьте TLS и контроль доступа средствами развертывания. Эталонный сценарий использует заранее подготовленные локальные образы и изолированные сети с Bifrost v2.4.0 и синтетическим сервером модели.

## Запуск и подключение

Выполняйте команды из корня Product-security-skills с Python 3.11+. В примерах используются синтетические политики. Перед адаптацией согласуйте политики приложения, их независимо закрепленные хеши, адреса и учетные данные.

```sh
export PYTHONPATH="$PWD/tools/prompt-guard/src:$PWD/tools/prompt-integrity/src:$PWD/integrations/bifrost"
python3 integrations/bifrost/example_integrity.py
python3 integrations/bifrost/stage_skills.py /tmp/product-security-skills-import
```

Выберите новый каталог подготовки с существующим родительским каталогом. В Bifrost создайте каждый скилл с его исходными метаданными, вставьте основной текст Markdown без блока метаданных и загрузите вспомогательные каталоги с сохранением относительной структуры. Проверьте подготовленные файлы и отдельно разрешите публикацию. Размещение скилла предоставляет ассистенту инструкции; за проверки при работе с моделью отвечают выбранные компоненты интеграции.

В исходном руководстве приведены отдельные примеры входного фасада, окончательной отправки и работы с агентом, команды оценки маршрута и локальных тестов, а также эталонные сценарии с подготовленными образами: текстовый обмен, вызовы инструментов в JSON и буферизованный поток SSE.

## Идентификация маршрута и оценка

Оценка маршрута сохраняет результаты проверки поведения с `eligible=false`: обнаруженные нарушения дают `fail` и код выхода 1; иначе общий итог - `inconclusive` и код выхода 2. Проверка квитанции ответа подтверждает заявление издателя, связанное с запросом, ответом и идентификаторами маршрута с помощью HMAC. Какие именно веса и ревизии обслуживали запрос, необходимо подтверждать независимо; у квитанций сохраняются `weights_attested=false` и `eligible=false`. Если включить обязательный допуск через Model Security Eval, запрос будет остановлен до отправки модели. Используйте путь Guard/Integrity для проверки запросов и ответов, а результаты оценки маршрута - для анализа поведения.
