# Контроль целостности инструкций: prompt-integrity

`prompt-integrity` — самостоятельная Python-библиотека и CLI для проверки статических инструкций приложения непосредственно перед отправкой запроса модели. Версия 0.1.0 поддерживает ограниченный набор форматов запросов к Ollama `/api/chat` и LM Studio `/v1/chat/completions`; адаптер LM Studio также проверяет закрепленные определения инструментов.

[Исходники и руководство](https://github.com/defrixx/Product-security-skills/tree/main/tools/prompt-integrity) | [Скиллы и общий процесс](../security-skills/overview.ru.md)

## Что проверяет инструмент

Приложение загружает утвержденный эталон с заданными идентификатором профиля и версией. Эталон содержит точную начальную последовательность сообщений `system`. В нем также заданы допустимые роли последующих сообщений, соответствие псевдонимов целевым моделям и ограничения на использование ресурсов.

`verify_and_send` создает снимок запроса, проверяет его и передает транспортному компоненту те же неизменяемые байты. Изменение текста инструкций, порядка или ролей, неизвестная модель и неподдерживаемые поля блокируют отправку. Пробелы, переводы строк, регистр и различия Unicode значимы; эквивалентное JSON-экранирование допускается.

Проверка `check_request` предназначена только для диагностики: ее успешный результат не разрешает позже отправить изменяемый исходный объект. При повторной попытке или переключении на резервную модель приложение снова вызывает `verify_and_send`.

## Поддерживаемый формат

Адаптер `ollama-chat-text-v1`, версия `1`, принимает только `model`, `messages` и `stream: false`. В каждом сообщении допустимы только поля `role` и `content`, причем `content` должно быть строкой. За одним или несколькими сообщениями `system`, точно совпадающими с эталоном, могут следовать разрешенные эталоном сообщения `user` и `assistant`.

Адаптер Ollama не принимает определения инструментов, изображения, поле `options` и другие дополнительные поля.

Отдельный адаптер `lmstudio-chat-tools-v1`, версия `1`, задает в `allowed_request_fields` точные допустимые JSON-значения полей `stream: false`, `temperature`, `max_tokens` и `tools`. Описания инструментов и схемы параметров входят в доверенный эталон. В запросах ассистента на вызов инструментов допускаются только закрепленные имена инструментов и уникальные идентификаторы вызовов. До следующего обычного сообщения в истории должны присутствовать результаты всех этих вызовов с соответствующими идентификаторами. Неизвестные поля, дополнительные сообщения с инструкциями в ролях `system`/`developer`, мультимодальные данные и незавершенная история вызовов отклоняются. Задайте `HTTPTransport(..., path="/v1/chat/completions")` и тот же путь в целевых URL; по умолчанию транспорт использует `/api/chat`.

Закрепленная схема параметров сама по себе не обеспечивает проверку аргументов вызова или полномочий на его выполнение: обе проверки выполняет приложение. Результаты инструментов и текст пользователя с попыткой переопределить инструкции остаются недоверенными данными; инструмент не классифицирует внедрение инструкций. Responses API, потоковая передача и произвольные поля API, совместимых с OpenAI, не входят в охват этих адаптеров.

## Установка и CLI

Нужны Python 3.11+ и POSIX для файловых операций. Во время работы используются только модули стандартной библиотеки. Установите пакет из локальной копии репозитория в окружение приложения:

```sh
python -m pip install /path/to/Product-security-skills/tools/prompt-integrity
```

Для ознакомления используйте файлы с искусственными тестовыми данными из `examples/`. Замените пути абсолютными путями без символических ссылок:

```sh
prompt-integrity baseline validate --baseline /path/to/examples/baseline.json --config-root /path/to/examples --expected-profile synthetic-support --expected-version 1
prompt-integrity request check --baseline /path/to/examples/baseline.json --request /path/to/examples/request.json --target primary --config-root /path/to/examples --expected-profile synthetic-support --expected-version 1
prompt-integrity baseline create --instructions /path/to/examples/instructions.json --policy /path/to/examples/policy.json --output /path/to/examples/new-candidate.json --config-root /path/to/examples --expected-profile synthetic-support --expected-version 1
```

Команды CLI не вызывают модель. Код завершения `0` означает успех выбранной операции, `2` — отклонение запроса по политике целостности, `1` — ошибку конфигурации, ввода-вывода, ресурсов или внутреннюю ошибку. Команда создания эталона записывает предварительный вариант для проверки и утверждения; существующий файл не перезаписывается.

## Подключение к приложению

```python
from prompt_integrity import load_policy, verify_and_send
from prompt_integrity.transport import HTTPTransport

policy = load_policy(
    "/protected/baseline.json", "synthetic-support", "1",
    config_root="/protected",
)
transport = HTTPTransport((("primary", "http://127.0.0.1:11434/api/chat"),))
# Объект request формируется приложением.
response = verify_and_send(policy, request, "primary", transport)
```

Перед реальным вызовом настройте утвержденный эталон и реальные модели: имена моделей в примерах вымышленные. Защитите эталон от изменений через недоверенные пути; ожидаемые идентификатор профиля и версия поступают из доверенной конфигурации развертывания. Проверка схемы не подтверждает происхождение или утверждение эталона. Загруженная политика неизменяема; обновление и откат требуют явно выбранной версии и перезапуска процесса либо повторной загрузки политики доверенным кодом.

Все обращения к модели, фоновые задачи, повторные попытки и резервные маршруты должны проходить через обертку. Не изменяйте входные объекты параллельно с созданием снимка. Собственная реализация транспорта остается доверенным компонентом и должна отправлять переданные байты без изменений.

Встроенный `HTTPTransport` не выполняет перенаправления, не использует прокси и не повторяет запросы автоматически. HTTPS проверяет сертификаты средствами платформы; незашифрованный HTTP разрешен только для адресов обратной петли. Размер ответа ограничен. `IntegrityError` возникает до отправки; `TransportError` означает ошибку транспорта после успешной проверки и не гарантирует, что сервер не получил запрос. Ни одна из ошибок не разрешает обход проверки.

Чтобы закрепить точное содержимое утвержденного эталона, передайте `expected_sha256` в `load_policy` либо `--expected-sha256` командам CLI `baseline validate` и `request check`. Хеш вычисляется по байтам утвержденного файла, включая пробелы, и хранится в отдельно защищенной конфигурации выпуска. Если при запуске вычислять ожидаемый хеш по файлу, который предстоит проверить, такая проверка теряет смысл. При несовпадении хеша загрузка останавливается; переход к эталону без проверки хеша не допускается. При обновлении или откате совместно выбираются профиль, версия и хеш эталона; это не проверка подписи и не защита от изменения доверенной конфигурации выбора выпуска. Целевые адреса транспорта настраиваются отдельно и не входят в содержимое файла, для которого вычисляется хеш.

Используйте поле `TransportError.code` с фиксированным набором кодов ошибок, чтобы различать тайм-аут, сбой соединения, отклонение HTTP-запроса, запрет перенаправления, превышение размера ответа, неверную конфигурацию транспорта и прочие транспортные ошибки. Исходный текст исключений, тела ответов и URL в диагностику не включаются. При повторной попытке приложение должно учитывать, что тайм-аут мог произойти после получения запроса сервером и повторный запрос может привести к повторному выполнению операции.

## Границы защиты и проверки

Инструмент проверяет наблюдаемый запрос. Он не гарантирует выполнение инструкций моделью, устойчивость к внедрению инструкций, безопасность ответа или корректность проверки полномочий на действия. Обход обертки, скомпрометированный процесс и одновременный контроль над эталоном и проверяющим кодом находятся вне защиты.

Для файловых операций нужно явно задать корневой каталог. Пути с символическими ссылками, входные файлы с жесткими ссылками и объекты, не являющиеся обычными файлами, отклоняются. Гарантии не распространяются на подмену каталогов атакующим во время файловых операций. Прерванная запись предварительного эталона может оставить неполный файл: перед утверждением его нужно проверить, а для повторной записи выбрать новый путь.

[Тесты пакета](https://github.com/defrixx/Product-security-skills/tree/main/tools/prompt-integrity/tests) проверяют изменение инструкций, структуру запроса, снимок, повторные попытки, CLI, файловые ограничения и локальный HTTP. Они используют искусственные тестовые данные и не требуют модели. Перед применением в своем приложении проверьте все точки отправки и транспортные перехватчики; тесты пакета не подтверждают отсутствие обхода в вашей интеграции.

Зафиксируйте основные обращения к модели, фоновые задачи, повторные обращения после вызовов инструментов, повторные попытки и резервные маршруты в [отчете об интеграции](https://github.com/defrixx/Product-security-skills/blob/main/tools/prompt-integrity/examples/integration-report.md), приложив подтверждение отправки именно проверенных байтов запроса, а также перечень непроверенных маршрутов. [Скрипт испытаний моделей](https://github.com/defrixx/Product-security-skills/blob/main/evals/README.md) проверяет каждый исходящий запрос Chat Completions только при выборе `--integrity`; эталон, используемый в эксперименте, не утвержден для развертывания приложения. Запуски Chat без проверки целостности и запуски Responses остаются отдельными режимами испытаний.
