Начните с архитектурного ревью или модели угроз. Для решений о выпуске и работы с найденными уязвимостями выберите соответствующий плейбук.

| Задача | Документ | Охват проверки |
| --- | --- | --- |
| Проверить архитектуру | [Архитектурное ревью](/Product-security-playbook/ru/review/architecture/checklist/) | Границы системы, потоки данных и архитектурные решения |
| Построить модель угроз | [Моделирование угроз](/Product-security-playbook/ru/review/threat-modeling/playbook/) | Сценарии угроз для выбранной системы или изменения |
| Подготовить выпуск | [Управление выпуском](/Product-security-playbook/ru/review/release-governance/playbook/) | Условия выпуска и решения об остаточном риске |
| Организовать работу с уязвимостями | [Управление уязвимостями](/Product-security-playbook/ru/review/vulnerability-management/playbook/) | Разбор, приоритизация и сопровождение исправлений |

## Как выстроить проверку

- Для нового сервиса начните с архитектурного ревью: определите границы системы и рассматриваемые потоки данных. Перейдите к моделированию угроз, чтобы разобрать сценарии злоупотреблений в этих границах.
- Для изменения существующего сервиса выберите затронутые части архитектуры и модели угроз. Таблица выше поможет перейти к нужному документу без повторного прохождения всего раздела.
- Перед выпуском используйте плейбук управления выпуском. Если основная задача — обработать уже найденные проблемы, начните с управления уязвимостями.

## Когда нужны другие разделы

Для проверки кода, API и веб-приложений перейдите в раздел [безопасности приложений](/Product-security-playbook/ru/application-security/overview/). Проверки Kubernetes и Vault собраны в разделе [безопасности платформы](/Product-security-playbook/ru/platform-security/overview/).
